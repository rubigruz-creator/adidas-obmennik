ПРИОРИТЕТ 1: ПРЕДПРОСМОТР ФАЙЛОВ (ЭСКИЗЫ-ПРЕВЬЮ)
Добавить в приложение эскизы изображений для улучшения визуального восприятия.

Требования:

1.1. Эскизы в меню файла (BottomSheet)
- В верхней части меню, над названием файла, должно отображаться превью:
  - Для изображений (jpg, jpeg, png, webp, gif, bmp) — миниатюра самого изображения
  - Для других типов — иконка FileIcon (уже есть)
- Размер превью: примерно 200×150px
- Скруглённые углы, тень
- Если изображение не загрузилось — показывать иконку типа файла

1.2. Эскизы на главном экране в режиме сетки (FileCard)
- В карточке сетки (2 колонки) вместо иконки FileIcon показывать:
  - Для изображений — маленький эскиз (thumbnail) самого изображения
  - Для других типов — иконку FileIcon (как сейчас)
- Размер эскиза: примерно 80×60px
- Эскиз должен вписываться в карточку, сохраняя пропорции (BoxFit.cover)
- Скруглённые углы

1.3. Генерация эскизов на сервере
- Для получения эскизов использовать существующий API download.php, добавив параметр ?thumbnail=1
- Сервер должен при thumbnail=1 возвращать уменьшенную копию изображения (например, 200px по большей стороне)
- Для не-изображений thumbnail=1 игнорируется или возвращает ошибку 400

1.4. Кэширование эскизов на клиенте
- Эскизы кэшировать локально, чтобы не загружать повторно
- Использовать пакет cached_network_image или flutter_cache_manager
- Ключ кэша: file_id

1.5. Важно
- Не сломать существующий FileIcon для не-изображений
- Не менять серверную логику кроме добавления параметра thumbnail в download.php
- В режиме списка (FileListTile) оставить иконки как есть (36px)

3.3.2. Отображение описания в меню файла (BottomSheet)

  - Максимум 3 строки, с многоточием если длиннее
  - Если description пустой или null — не показывать

3.3.3. Передача description в API
- В ApiService.uploadFile добавить параметр description (String?, опционально)

3.3.4. Отображение в карточках

3.4. Ограничения
