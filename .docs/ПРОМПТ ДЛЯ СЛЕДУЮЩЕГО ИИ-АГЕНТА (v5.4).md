**Подзадача 1.1: Множественная загрузка файлов**
- Выбор нескольких файлов одновременно через FilePicker (`allowMultiple: true`)
- Последовательная или параллельная загрузка с индивидуальным прогрессом
- Отображение прогресса для каждого файла (список в диалоге)
- Обработка ошибок: часть файлов загрузилась, часть нет
- Кнопка отмены для каждого файла
- Работает в обеих версиях (Android + Web)
- **Файлы:** `lib/screens/upload_operations.dart`

**Подзадача 1.2: Множественная обработка (удаление, перемещение)**
- Режим выбора файлов:
  - Долгое нажатие для входа в режим выбора

- AppBar меняется: показывает количество выбранных, кнопки действий
- Групповое удаление выбранных файлов (с подтверждением)
- Групповое перемещение в папку
- Выход из режима выбора по кнопке "Отмена"
- **Файлы:** `lib/screens/file_operations.dart`, `lib/screens/files_screen.dart`

**Важно:** Сохранить обратную совместимость с текущим одиночным режимом.

### ЗАДАЧА 2: 🧾 Аудит действий пользователя

**Цель:** Записывать историю всех действий с файлами и папками.

**Что логировать:**
- Кто загрузил/удалил/переименовал/переместил файл
- Кто создал/удалил/переименовал папку
- Кто изменил видимость файла (личный/общий)
- Кто скачал файл
- Кто создал публичную ссылку
- Кто вошёл/вышел из системы

**Реализация:**

**Сервер:**
- Новая таблица `audit_log` в MariaDB:
  - `id INT AUTO_INCREMENT PRIMARY KEY`
  - `user_id INT NOT NULL`
  - `action VARCHAR(50) NOT NULL` (upload, download, delete, rename, move, toggle_visibility, create_folder, delete_folder, rename_folder, share_link, login, logout)
  - `file_id INT DEFAULT NULL`
  - `folder_id INT DEFAULT NULL`
  - `details JSON DEFAULT NULL` (старое имя, новое имя, размер и т.д.)
  - `created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP`
  - FOREIGN KEY (user_id) REFERENCES users(id)
- Новый эндпоинт `audit_log.php` (только для админов):
  - GET-параметры: `user_id`, `action`, `date_from`, `date_to`, `limit`, `offset`
  - Возвращает JSON с логами
- Обновить существующие PHP для записи логов:
  - `upload.php` — логировать загрузку
  - `delete.php` — логировать удаление
  - `rename.php` — логировать переименование
  - `toggle_visibility.php` — логировать изменение видимости
  - `move_file.php` — логировать перемещение
  - `download.php` — логировать скачивание
  - `create_folder.php` — логировать создание папки
  - `delete_folder.php` — логировать удаление папки
  - `rename_folder.php` — логировать переименование папки
  - `get_share_link.php` — логировать создание ссылки
  - `login.php` — логировать вход
  - `logout.php` (создать если нет) — логировать выход

**Клиент:**
- Новый экран «История» (`lib/screens/audit_screen.dart`):
  - Доступен только администраторам (проверка `admin`)
  - Таблица/список с логами
  - Фильтры: по пользователю, по действию, по дате
  - Пагинация (подгрузка при скролле)
  - Отображение: когда, кто, что сделал, с каким файлом/папкой
- Новый метод в `ApiService`: `getAuditLogs(token, {userId, action, dateFrom, dateTo, limit, offset})`
- Добавить кнопку «История» в интерфейс (например, в профиль или AppBar)

## 📌 ВАЖНЫЕ ОГРАНИЧЕНИЯ
- **Не сломать текущий функционал.** Все изменения обратно совместимы, Android-сборка должна проходить успешно
- **Единая кодовая база.** Использовать условные платформенные проверки (`kIsWeb`), не создавать отдельные проекты
- **Код должен быть чистым.** Соблюдать архитектуру (миксины, разделение на экраны/сервисы/виджеты)
- **Веб-версия деплоится** на сервер через `scp` после сборки
- **Все новые файлы коммитить** в ветку `feature/web-version`
